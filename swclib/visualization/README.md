# SWC Studio

swclib 自带的本地可视化网站，版本 **0.8.0**。全部实现位于 `swclib/visualization/`，复用现有 SWC 和全脑读取器。无需 Node.js、前端构建、CDN 或 Python 调用代码。

## 安装和启动

在仓库根目录、需要使用的 Python 环境中执行：

网站服务要求 Linux 和系统 `libseccomp.so.2`（Debian/Ubuntu 软件包名 `libseccomp2`），用于强制执行文件只读保护。当前开发环境已提供；缺少保护支持时服务拒绝启动或拒绝处理请求，不降级为可写访问。

```bash
pip install .
swclib-viewer --port 8000
```

浏览器打开 `http://127.0.0.1:8000`。需要边开发边使用时改为 `pip install -e .`。

```bash
# 启动后自动打开浏览器
swclib-viewer --port 9000 --open

# 预先登记数据源；参数可重复，路径可为文件或目录
swclib-viewer --port 9000 --swc /data/neurons --image /data/blocks

# 进一步收紧单个浮点显示体的容量上限
swclib-viewer --port 9000 --max-volume-mib 32

# 指定 SWC 解析进程数（1..8）；默认按 CPU/内存自动选取，最多 4 个
swclib-viewer --port 9000 --swc-workers 4

swclib-viewer --help
swclib-viewer --version
```

预登记的 SWC 自动显示，图像只登记路径。网页中填写的路径均位于**服务所在计算机**上。默认只绑定 `127.0.0.1`，远程服务器可以通过 SSH 转发使用：

```bash
ssh -L 8000:127.0.0.1:8000 user@server
```

`--host` 可以修改监听地址。本服务面向可信的本机环境，不提供多用户身份认证；访问者可请求读取服务进程有权限读取的数据文件。

## 神经元

- 文件路径加载单个 `.swc`，目录批量加载，可勾选包含子目录。
- 右侧列表独立切换可见性，支持全显、全隐。
- 每行左侧的选择框用于批量移除，与显示开关独立；每行 `×` 可单项移除。“选择全部 → 移除所选”支持清空当前列表。移除释放几何缓存，不删除磁盘上的 SWC，可以重新添加。
- 节点大小使用屏幕像素，缩放时大小保持稳定；支持显示/隐藏节点、连线及标注不透明度。
- 两种颜色模式可随时切换：
  - **节点拓扑**：根节点蓝色，度数为 2 红色，度数大于 2 绿色，叶子黄色。度数是无向图相邻边数，根节点颜色优先。
  - **神经元颜色**：每个 SWC 使用一种稳定、不同的颜色，列表右侧显示对应色标。
- 三维模式中左键采用轨迹球自由旋转：视口中部拖动改变观察方向，靠近视口边缘绕圈拖动可绕视线滚转，也可用 Alt + 左键水平拖动单独滚转。旋转使用归一化四元数，可连续组合任意方向，不受固定世界竖直轴或上下极点限制。右键拖动或 Shift + 左键平移，滚轮缩放，`F` 或“适应视图”居中并调整缩放。XY/XZ/YZ 正交视图仍保持对应切片方向，返回三维后恢复此前的自由旋转姿态。
- 左下角 XYZ 方向轴随相机同步：X 红、Y 绿、Z 蓝，字母端表示正方向，虚线端表示负方向。正交视图同步对应的固定方向。独立小画布仅在方向/尺寸变化时更新，不增加 SWC 的 GPU 绘制调用。
- 右侧顶部“视野中心”可输入 XYZ 后定位，保持当前缩放和旋转角度；“获取当前中心”回填当前值。使用当前显示坐标，启用 crop 后为减去 start 的局部坐标。正交视图定位时同步对应切片，超出图像范围的切片位置限制在有效范围内。
- 仅绘制节点与父节点之间的直线，不依赖 SWC 半径绘制管道。

### 点击目标与整体中心

在视口内右键单击，选择 **Go to target**，将视野中心移到命中的显示坐标，保持缩放和旋转。菜单会先显示目标 XYZ；点击空白处时按钮禁用，按 Escape 或点击其他位置关闭。拖动右键仍是平移，不弹菜单。

- 优先查找点击处的可见 SWC 节点/连线，线段可定位到中间位置；遵守点线显隐、切片半厚度与 crop 后的局部坐标。选取采用至少 4 个屏幕像素的容差，重叠位置选择靠近观察者的目标。
- 未命中 SWC 时查找当前图像：正交视图定位到当前切片；MIP 定位到视线上最亮信号的采样位置；体渲染定位到该视线中贡献最大的采样位置。三维投影没有唯一深度，图像目标采用与显示一致的采样步长，属于采样位置而非人工标注点。
- 工具栏 **整体中心** 回到当前全部可见 SWC 与当前图像联合包围盒的中心，保持缩放/旋转。隐藏数据不参与计算；正交视图同步中心对应的切片。**适应视图** 还会调整缩放以容纳全部可见数据。

命中计算只在右键单击时执行：SWC 在已有几何 Worker 中查询，图像仅渲染两个离屏像素并读取命中深度，复用当前纹理；不增加常规帧的 SWC 绘制调用，也不为定位保留额外的整幅 CPU 图像副本。视角、数据或显示设置变化会使未确认的目标失效。

### Crop 与坐标

所有界面坐标均按 **X, Y, Z** 输入，支持逗号或空格分隔。区域是 **`[start, end)`**，start 包含、end 不包含；保留的 SWC 坐标自动减去 start。重置后恢复原始数据，不写入原文件。

裁剪复用 `Swc.read_region`：只保留区域内的节点及两端均保留的连接；父节点在区域外的节点成为新的蓝色根节点。颜色依据裁剪后的拓扑计算。不额外创建线段与裁剪盒交点处的虚拟节点。

### 批量并行加载

浏览器通过有上限的请求队列读取 SWC，服务端使用独立进程并行执行现有 `Swc` 解析和裁剪，避免 Python GIL 使解析仍然串行。默认进程数取 CPU 可用核心数、每进程 256 MiB 的启动余量及 4 的最小值，至少为 1；可用 `--swc-workers 1..8` 调整，`1` 表示串行读取。右侧显示进程数和处理进度。

进程在服务启动时预热；每个进程安装同样的 seccomp 只读保护，进程间只传输紧凑二进制数据，不传输逐节点 Python 对象。多个标签页共享服务端并发上限；读取至 HTTP 传输完成始终占用名额。按文件大小的 32 倍（至少 8 MiB）预留解析、crop 副本和传输开销，同时受可用内存的 20% / 2 GiB 预算限制；预算不足时排队，单文件超过预算时明确拒绝。这是保守估计，不是严格的进程内存上限。

同一批次的结果交给 Web Worker 后统一组装、上传 GPU，避免每完成一个文件就重建全部几何。保留完整点线和两种颜色；隐藏、移除、再次 crop 后的过期结果不会覆盖新场景。图像仍使用独立的串行读取队列，仅显示一幅。

2026-10-13 实测：相同的 **32 个 SWC × 每个 10,000 节点**，文件缓存预热后交替测试三轮，单进程 HTTP 加载中位数 **2.323 秒**，4 进程 **0.810 秒**，约 **2.87 倍**。结果二进制 SHA-256 完全一致。测量包含解析、进程间传输、HTTP 传输和校验，不含浏览器/GPU 上传及服务启动；环境允许 128 个 CPU 核心。实际提升取决于 CPU、存储和单文件大小，小文件及慢磁盘不保证同等加速。

复现命令（只在指定输出目录生成测试数据）：

```bash
python swclib/visualization/tests/loading_benchmark.py --output /tmp/swclib-loading-check
```

## 小块图像与叠加

支持二维/三维**单通道灰度** TIFF、NRRD、NPY。数组存储顺序为 **ZYX**，二维图像作为深度 1 的体显示；界面尺寸以 XYZ 展示。RGB、额外通道/时间轴需要先提取为单个灰度体。TIFF 使用第一个图像 series，NPY 禁用 pickle。

目录批量添加只登记路径，不读取所有文件的头信息或像素。选择后才查看元数据、验证容量、读取像素。每次只保留一幅图像纹理；选择另一幅会立即释放旧纹理，取消显示也会释放。服务端没有图像缓存；已开始的单次解码会完成并释放，过期结果不会显示，待处理的过期请求直接跳过。多个标签页的图像解码/传输在服务端串行执行，避免同时产生多个图像解码峰值；SWC 使用上述独立的并行队列。

图像和全脑裁剪小块均支持每行 `×` 单项移除及勾选后批量移除，选择框不触发图像加载。移除当前图像会释放纹理并取消待显示结果；源图像和全脑目录保持不变。读入中的条目被移除后，其迟到结果不会重新出现在场景中。

图像模式包括三维最大强度投影（MIP）、三维体渲染，以及 XY、XZ、YZ 正交切片。可调整黑场、白场、亮度、Gamma、不透明度和自动对比度；切片滑块控制位置，“SWC 切片半厚度”控制同时显示的标注范围。

图像用 **float32 纹理**显示，保留 uint8/uint16 原始灰度的区分能力，避免先量化到 8 位而抹掉弱信号。范围线性归一化后，亮度和对比度全部在 GPU 上调整，不重新读取文件。浮点线性过滤不可用时，shader 使用手动三线性插值。非常大整数/高动态范围浮点值仍受 float32 精度限制。

“小块图像全局起点”指定其第一个体素的 SWC 坐标，默认 `(0, 0, 0)`。若小块由相同 SWC crop 导出，点击“对齐 SWC crop”即可对齐。启用 SWC crop 时，图像显示起点也减去该 start。

本版本使用体素坐标，不自动应用 TIFF/NRRD 的物理 spacing、FNT direction 或 affine。用于叠加的 SWC 必须位于对应图像的同一体素坐标系。

## 全脑数据

在“图像 → 从全脑数据读取区域”中登记目录：

- **FNT**：目录内包含 `catalog` 及 NRRD 分块，通道默认 `ch00`；复用 `WholeBrainReader(mode="fnt")`，只解码相交的 cube。
- **TIFF 切片**：二维灰度切片目录，复用 `WholeBrainReader(mode="slice")` 和 raster 窗口读取。正则必须含一个 Z 索引捕获组，例如 `slice_(\d+)\.tif`，扩展名默认 `.tif`。遵循现有读取器要求：Z 索引唯一、连续，可以非零起始。

全脑目录放在“已登记的全脑数据源”选择框中，不再作为图像列表中的一个可显示条目。选择数据源，输入整数 crop start/end，按 **添加并显示小块**。图像列表为每个区域添加独立条目，名称格式为 **`brain-name_[x0,y0,z0]-[x1,y1,z1]`**，例如 `brain01_[30,20,5]-[50,40,25]`；brain-name 取全脑目录名，end 不包含。

同一来源/模式/通道/区域重复添加会复用原条目。不同区域各自保存固定坐标，点击旧条目会重新读取它自己的区域，不受输入框后续修改影响。仅保存读取参数，不向源目录导出文件，也不缓存未选中的小块像素。每次仍只显示一幅图像；区域登记和实际读取都会检查 300³ 上限、内存预算及全脑边界。

选择框旁的“移除”仅移除全脑数据源登记；已创建小块保存完整的来源参数，可继续显示或在图像列表单独/批量移除。“使用 SWC crop 坐标”可复制已应用的区域。小块保留全局起点；SWC 启用相同 crop 后，两者自动减去相同 start。

### 容量估计

图像及全脑 crop 的硬上限为 **300 × 300 × 300**：X、Y、Z **每个轴均不超过 300**，最多 27,000,000 体素。不是只限制体素乘积，例如 301×10×10 也会拒绝。默认显示体内存预算提高为 **128 MiB**，可容纳完整 300³ float32 纹理（约 103 MiB），同时受以下更小上限约束：

1. 当前可用内存及 Linux cgroup 剩余内存的 20%，最多使用 2 GiB 作为峰值预算。
2. 原始 dtype、输出/传输/纹理副本、归一化工作区和单个解码块/切片的开销；TIFF 还预留 16 MiB GDAL 缓存。
3. 浏览器实际 `MAX_3D_TEXTURE_SIZE`（硬上限仍为单轴 300）。
4. `--max-volume-mib` 配置的容量上限。

读取前重新计算限制。超过体素总数、单轴大小或解码预算就拒绝，不偷偷降采样或加载整个全脑。全脑解码使用一个 worker，限制同时解码的工作块。该值是面向交互的**保守容量估计，不是帧率承诺**；显卡、分辨率、数据压缩和存储速度都会影响速度。低性能环境可调小上限或使用正交切片。

## 插件 · 查看胞体

右侧工具栏依次为 **神经元 SWC / 图像 / 插件**。“插件”中每个插件可单独折叠或展开。**查看胞体** 的用法：

1. 输入全脑目录，选择 FNT（含通道）或 TIFF 切片（含文件名规则）模式。
2. 输入 crop 立方体边长，单位为体素，范围 1–300；仍受当前内存容量约束。
3. 输入 neuron SWC 文件或目录，可勾选递归扫描，点击“识别胞体候选”。
4. 点击候选，加载该 SWC 在区域内的节点/连线和对应图像，并将视野中心放到候选位置。此前显示的其他 SWC 隐藏、图像被替换，列表登记保留。

候选规则按**每个 SWC 文件**计算：优先列出全部 `type=1` 节点；一个也没有时，列出全部 `parent=-1` 根节点，并标记“根节点候选”。同一文件有多个候选时分别列出节点 ID 和全局 XYZ。只读取原始节点位置，不拟合胞体球、不自动修正位置，也不把根节点当作已确认的胞体。坏文件和无候选文件在列表中说明，其他文件继续处理。候选支持名称/节点 ID 筛选，每页最多 50 项以限制 DOM 数量。

SWC 必须使用对应全脑的**全局体素 XYZ 坐标**。以候选为中心计算整数半开 crop，靠近数据边界时向内平移，保持指定立方体边长；超出全脑范围的候选不可点击。全脑任一轴不足边长时明确提示缩小边长。加载后图像和 SWC 均减去相同 start，视野中心也使用局部坐标。

扫描复用受限 SWC 进程池和只读保护，仅传回候选元数据；不加载图像像素，也不上传全部神经元几何。点击后才读取对应小块，图像列表沿用 `brain-name_region` 命名。图像和标注均读取成功后一起切换；读取失败时保留此前场景。快速切换、重新扫描、参数变更及手动切换数据会使过期显示请求失效。可取消扫描；已经开始的单次源文件读取会完成，结果丢弃，尚未开始的任务不再执行。

插件实现位于 `plugins.py` 和 `static/plugins.js`；内置插件注册表通过少量显示/读取接口接入现有视口，不加载用户提供的脚本。新增 `/api/somas` 接口只接收已登记 SWC 的 ID 和候选规则，与普通 SWC 读取共享并发和内存上限。

## 插件 · 划分脑区

先在 SWC 列表中加载并显示要划分的神经元，再展开“插件 → 划分脑区”，勾选 **显示划分平面**。首次启用时，默认平面垂直于 X 轴并经过可见数据中心；也可用“平面经过可见数据中心”重新居中。平面是半透明网格，视口内随相机变化显示“左半脑 −n”和“右半脑 +n”，正对平面时补充近侧/远侧提示。

**方位角、仰角、法向偏移**均支持输入和滑块，控件双向同步。方位角从 +X 朝 +Y 增大，按 360° 周期归一化；仰角范围为 −90° 到 90°、正向朝 +Z。设方位角为 a、仰角为 e，单位法向量为 `n=(cos(e)cos(a), cos(e)sin(a), sin(e))`，全局平面方程为 `n·XYZ=offset`。偏移滑块覆盖当前数据在法向上的投影范围，也会扩展到手动输入的值；偏移单位与 SWC 全局体素坐标相同。

有符号距离 `n·XYZ-offset` 的正侧为右、负侧为左；恰好在平面上的点归右。SWC crop 只平移显示坐标，不改变全局平面参数。拖动参数不会重读 SWC 或逐节点重新组装几何，启用时只增加一次平面绘制，关闭时恢复原有绘制次数。神经元原有拓扑/单神经元着色保持可用。

点击 **统计左右脑神经元数量**，统计当前已加载显示的完整 SWC，不受 crop 裁剪影响、不包含隐藏条目。分类沿用导出的两侧线段长度规则：完全左侧、完全右侧和跨两侧为互斥分类，三者之和为总数；左侧合计 = 完全左侧 + 跨两侧，右侧合计 = 完全右侧 + 跨两侧。无非零线段时沿用节点侧别兜底规则。数量统计无需唯一胞体候选，也不写入文件。修改平面或可见神经元后，旧结果会失效并提示重新统计；正在计算的旧请求返回后不会覆盖新状态。

点击 **微调平面并平衡两侧**，在当前法向量附近搜索适合比较训练／测试数据划分的平面。**最大调整角度默认 10°**，可输入 0–90°；0° 仅居中。每个候选均严格经过点击时可见数据的包围盒中心，与“平面经过可见数据中心”使用同一范围（可见 SWC 的显示几何及当前图像；crop 后换算回全局 XYZ）。这是位置硬约束，因此原平面偏离中心较远时，法向偏移也可能明显变化；角度上限只约束法向转角。

排序规则：先争取使 `|完全左侧数 − 完全右侧数| < 5`；满足时优先跨侧数更少，再比较数量差和转角。若搜索中没有候选达到该阈值，则先比较数量差，再比较跨侧数和转角。采用有限的粗网格和局部细化搜索，保留原方向居中后的候选，不保证全局最优。最多提供 **3 个方向有区别的建议平面**，默认应用排名第一的结果；下拉切换即预览，并同步显示完全左／右和跨侧数量。候选均受同一个原始方向及角度上限约束，切换不会累计旋转；导出使用当前选中的平面。候选之间尽量至少相隔 `min(2°, 上限/3)`。修改平面、可见神经元或角度上限后候选失效；搜索期间可见中心变化也会阻止应用过期结果。

搜索分类仍使用可见神经元的**完整原始 SWC**。普通 SWC 读取会顺带生成轻量几何摘要，搜索时复用；缺失时通过受限进程池按文件准备，不合并全部节点。优先保留最多 512 个凸包支撑点，并逐点验证保守投影误差界；退化几何使用分块包围盒。摘要能确定分类时直接计算，临界候选则读取完整几何精确判断，**不按抽样比例估计数量**。摘要缓存最多 64 MiB（另受可用内存比例限制），按文件大小、修改时间等失效；所有源文件只读。点击搜索不写结果文件。

本机 4 进程实测（Intel Xeon Platinum 8358P 2.60 GHz，128 个可用逻辑 CPU）：`MADM-TBR2-I3/…/neurons-refined` 的 1004 个 SWC、49,604,050 个节点（2.85 GiB），从 X 法向、可见包围盒中心、10° 上限搜索 410 个候选，复用摘要后耗时 **4.78 秒**；完全无摘要缓存时合计 **94.69 秒**，其中首次读取和摘要准备 **90.31 秒**。计时包含搜索及必要的完整几何回退，不含进程启动、浏览器渲染和单独的导出算法复核；具体耗时随数据和机器负载变化。普通 SWC 显示加载会提前准备这些摘要。本次摘要缓存约 **8.04 MiB**，最佳候选分类与完整逐线段导出统计全量一致。

确定参数后，输入**服务端已有目录或具体 `.json` 文件路径**并点击 **导出 JSON**。填写目录时使用默认文件名 `brain_hemisphere.json`；填写文件路径时使用指定名称，父目录须已存在。目标已存在时弹窗显示完整路径并询问是否覆盖；取消保留原文件，确认后才替换。导出范围在点击时固定为当前已加载显示的 SWC，读取这些文件的**完整原始全局坐标**，不使用裁剪后坐标，也不包含隐藏条目。输出遵循给定示例的结构：

- `description`：法向正侧为右、负侧为左的说明。
- `plane`：`type`、`azimuth_deg`、`elevation_deg`、`normal_xyz`、`offset`、`point_xyz`；其中 `point_xyz=offset*n`。
- `neurons`：每个神经元的 `swc_name`、`soma`（`x/y/z/side/signed_distance`）、`right_length`、`left_length`、`total_length` 和 `hemisphere`（`left/right/cross`）。

跨平面的线段按精确交点比例分配长度，不按节点数估计，也不重新采样。两侧都有正长度的神经元标为 `cross`；没有非零长度线段时按节点所在侧分类。胞体使用唯一的 `type=1` 节点；没有 type=1 时使用唯一根节点。多个候选、没有候选、坏文件、无效父节点或不同目录内同名 SWC 会明确报错并阻止整次导出，不输出部分结果。

统计和导出复用只读 SWC 进程池及其并发/内存预算。写入由启动时创建的专用线程完成，只接受目录或 `.json` 目标；首次请求不覆盖已有文件，确认后通过临时文件原子替换。全部统计和 JSON 编码成功后才发布，失败时保留原结果；覆盖链接路径只替换该路径，不修改链接指向的源文件。

## 源数据只读保护

- 请求线程及每个 SWC 读取子进程在读取源文件前安装 Linux seccomp 规则，阻止带写入/创建/追加/截断标志的文件打开，以及删除、重命名、链接、权限、时间戳等文件修改操作；原生 TIFF/NRRD 读取代码和新建解码线程也受限制。只读文件打开、HTTP 响应和标准输出仍可使用。规则通过 [libseccomp API](https://github.com/seccomp/libseccomp/blob/main/include/seccomp.h.in) 安装，依据 [Linux seccomp 机制](https://www.kernel.org/doc/html/v5.4/userspace-api/seccomp_filter.html) 执行。
- 请求字段有明确白名单；没有上传、源文件保存或磁盘删除接口。`/api/remove` 仅接受条目 ID，并仅删除内存中的登记记录。
- 唯一写入功能是手动触发 `/api/hemisphere/export`：服务端自己计算完整结果，由专用写入线程在指定目录或 `.json` 路径发布 JSON；已有结果须确认覆盖，请求线程和所有源数据读取子进程仍保持 seccomp 保护。
- SWC 裁剪使用内存副本，图像处理生成新的显示数组；NPY 使用只读映射且禁用 pickle，TIFF/NRRD 只读打开。不会给源目录创建 `.aux.xml` 等写入副产物。
- 对需要文件描述符的 SciPy/Qhull 诊断日志使用 Linux 匿名内存文件，不放宽 seccomp 的源文件写入限制，也不修改全局 `os` 或 `tempfile` 模块。
- 保护不通过更改源文件权限实现，也不影响其他程序对它们的权限；普通读取可能由操作系统更新访问时间 atime。测试校验源文件内容 SHA-256、mtime 和权限均不变。
- 该机制保护可视化服务的读取流程，不能约束其他进程或管理员操作。只读保护安装失败时返回 503，不继续处理数据。

## 渲染实现与性能

- WebGL2 原生绘制，不为每个节点/边创建 JavaScript 或场景对象，不抽样、不简化原始节点或边。
- 所有神经元共享交错顶点缓冲区和 uint32 索引缓冲区；节点一个 `POINTS` 调用，连线一个 `LINES` 调用。**无论加载多少神经元，SWC 为两次绘制调用。**
- 顶点每节点 20 字节，边每条 8 字节；每个神经元的可见性与颜色在小型 GPU 调色板中。颜色模式、可见性、点大小调整不重建几何数据。
- SWC 二进制传输（float32 坐标、RGBA8 拓扑色、uint32 索引）；Transferable ArrayBuffer 交给 Web Worker，由 worker 组装批次，避免主线程逐节点构造对象。
- 相机交互由 `requestAnimationFrame` 合并；静止时不持续渲染。使用设备原始像素密度和抗锯齿，不通过降低 SWC 分辨率换速度。
- 隐藏的已读 SWC 保留几何缓冲区，以便立即切换；其顶点被 GPU 裁掉。隐藏图像则释放纹理，不保留像素缓存。

2026-10-13 的 0.3.0 回归实测，Chromium 148，1280×900，**SwiftShader 软件渲染**（未使用实体 GPU），10 个神经元，默认节点 5 px，完整点线：

| 可见节点数 | 添加至可交互 | 连续旋转 | SWC 绘制调用 |
| --- | --- | --- | --- |
| 10,000 | 约 0.37 秒 | 约 37 FPS | 2 |
| 100,000 | 约 0.51 秒 | 约 8 FPS | 2 |

第二项缓冲区还包含前一项隐藏的 10,000 节点。数字包含当前测试机器负载，不代表所有设备。10 万节点的软件渲染仍存在性能边界，建议在启用硬件加速的目标浏览器上使用下述脚本复测。测试报告区分主线程提交时间和真实交互帧间隔，不将 WebGL 调用返回时间当作 GPU 完成耗时。
